# 同类项目与设计取舍

这些项目解决的问题有所不同。比较依据是各自公开 README 和项目介绍，目的是选出适合 OpenSquad 当前阶段的做法，并不代表功能优劣排名。链接中的功能可能继续变化。

| 项目                                                     | 主要方向                                                             | 对 OpenSquad 的参考价值                                          |
| -------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------- |
| [Mindcraft](https://github.com/mindcraft-bots/mindcraft) | 用 LLM 和 Mineflayer 控制 Minecraft 角色，提供动作与多智能体协作能力 | 借鉴动作库与行为反馈的分层，进一步研究协作中断和执行失败处理     |
| [Voyager](https://github.com/MineDojo/Voyager)           | 自动探索 Minecraft，以课程和不断扩展的技能库学习行为                 | 技能积累值得研究，但自主探索和与真人一起玩需要不同的产品评价方法 |
| [OpenGameMate](https://github.com/Remersal/OpenGameMate) | Windows 桌面陪伴，通过游戏画面和 ChatGPT Voice 进行交谈              | 借鉴先呈现玩法、展示真实效果、再提供下载和设置入口的文档顺序     |
| [AIRI](https://github.com/moeru-ai/airi)                 | 可交互的虚拟角色与陪伴体验，包含游戏交互方向                         | 借鉴多语言入口与面向玩家的产品叙述，角色体验可以先于技术架构介绍 |

OpenSquad 当前先做 Minecraft 里的协作体验。指令能直接触发动作，不要求玩家先开通模型账号，便于快速测试跟随、采集和交付是否好用。LLM 暂时负责自由聊天，后续若允许模型发起动作，也应通过已有技能接口执行，并明确处理取消、超时和失败；仅靠一段更像朋友的回复，并不能解决队友卡住或无法交付材料的问题。

README 因此先介绍一次可以尝试的合作，再说明安装和已知限制；开发者需要的接口与测试放到单独文档。暂时没有真人游戏录像，所以文档保留明确标注的指令示例，不把自动测试当作玩家实录，也不借用其他项目的演示画面。

重新核对公开首页后，值得延续的是入口与操作反馈：[AIRI 的中文首页](https://github.com/moeru-ai/airi/blob/main/docs/README.zh-CN.md)在开头提供语言和体验入口，[Mindcraft 的入门说明](https://github.com/mindcraft-bots/mindcraft#install-and-run)按下载、配置、启动世界和启动机器人展开。OpenSquad 的首次体验也应该让玩家知道何时可以继续操作，因此合作示例补充了等待采集回复的提示，并提供中文取回工具的写法。对早期队友产品，玩家能否完成一次合作比首页列出多少未来功能更有参考价值。
